# Supply chain

Every toolchain runs in the build container (`container/Containerfile`, used only
through `tools/dev.sh` / `tools/ci.sh`). Nothing is installed on the host. Each
external download comes from the official publisher and is verified. The
build fails if a checksum does not match.

Checked on 2026-11-01. When you bump a version, take the new checksum from the
same official source, update this table, rebuild the image and bump `IMAGE_TAG`
in `tools/dev.sh`.

### How the verification metadata was produced

```
tools/dev.sh ./gradlew --write-verification-metadata sha256 \
    ktlintCheck test testDebugUnitTest assembleDebug
```

Gradle records the SHA-256 of each artifact it downloads from the two official
repositories above. That is trust-on-first-use: Maven Central and Google Maven
publish no separate SHA-256 list to compare against. After adding or bumping a
dependency, run the same command, review the diff (only new components should
appear) and commit it together with the change.

## Not downloaded

- No adb, emulator or system images. The container has no USB access (`tools/dev.sh`
  passes no `--device` and no `--privileged`).
- No Gradle Plugin Portal, no JitPack, no other Maven repositories.
